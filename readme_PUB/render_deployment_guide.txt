1. ARCHITECTURE OVERVIEW: WHAT RUNS ON RENDER
--------------------------------------------------------------------------------
The project is configured so that a single Render Web Service hosts EVERYTHING:
1. Dynamic FastAPI ML Endpoints:
   - GET /api/predict              (2D thermal field & uncertainty inference)
   - GET /api/diagnostics/tchp     (Tropical Cyclone Heat Potential & D26)
   - GET /api/profile              (Vertical sounding column at any lat/lon)
   - GET /api/acoustics            (Mackenzie sound velocity & SLD detection)
   - GET /api/transect             (Zonal depth cross-sections)
   - GET /api/system/health        (Health check and model load status)
   - GET /docs                     (Interactive Swagger UI API documentation)
2. Interactive Web Application & 3D Volumetric Console:
   - GET /                         (Interactive Workstation & 3D Ocean Cube)
   - Serves all Three.js 3D shaders, Leaflet maps, and CSS/JS assets directly.
   - Built-in fallback routes for static JSON data (/api/metadata.json, 
     /api/argo_matchups.json, and /data/day_*.json).

2. PRE-DEPLOYMENT ESSENTIALS (ALREADY CONFIGURED & VERIFIED)
--------------------------------------------------------------------------------
The repository has been verified and hardened for Render:
✓ Path Resolution: `src/api/main.py` uses anchored `ROOT_DIR` so paths never 
  break regardless of the container execution folder.
✓ Port Binding: The start command binds to `0.0.0.0:$PORT` dynamically supplied
  by Render's environment.
✓ Static Asset Mounting: Both `dist/` (production bundle) and `web/` are mounted 
  so all UI scripts, images, and maps load without 404s.
✓ Requirements Hardened: `requirements.txt` includes FastAPI, Uvicorn, PyTorch, 
  NumPy, SciPy, Scikit-learn, and `aiofiles` (required for async static serving).
✓ Infrastructure-as-Code: `render.yaml` blueprint is created at project root.

3. METHOD 1: 1-CLICK BLUEPRINT DEPLOYMENT (FASTEST & RECOMMENDED)
--------------------------------------------------------------------------------
Render provides automated deployment via the included `render.yaml` file:

Step 1: Push your latest code to GitHub:
   git push origin main

Step 2: Log in to Render:
   Navigate to https://dashboard.render.com/ and log in with GitHub.

Step 3: Deploy via Blueprint:
   1. Click the "New +" blue button at the top right.
   2. Select "Blueprint".
   3. Connect your GitHub repository: "OceanEmbed" (or your repo name).
   4. Render will automatically read `render.yaml` and display:
      - Service Name: oceanembed-platform
      - Environment: Python
      - Build Command: pip install -r requirements.txt
      - Start Command: uvicorn src.api.main:app --host 0.0.0.0 --port $PORT
      - Health Check: /api/system/health
   5. Click "Apply".

That's it! Render will automatically install all dependencies, start Uvicorn,
and assign you a live HTTPS domain.

4. METHOD 2: MANUAL WEB SERVICE DEPLOYMENT
--------------------------------------------------------------------------------
If you prefer configuring the Web Service manually via Render's Web UI:

Step 1: Go to https://dashboard.render.com/
Step 2: Click "New +" -> "Web Service"
Step 3: Choose "Build and deploy from a Git repository" and select your repo.
Step 4: Fill in the configuration form with these exact settings:

   | Field               | Value to Enter                                          |
   |---------------------|---------------------------------------------------------|
   | Name                | oceanembed-api (or any unique name you prefer)          |
   | Region              | Oregon (US West) or Singapore (closest to Asia/India)   |
   | Branch              | main                                                    |
   | Root Directory      | OceanEmbed (leave blank if repo root is the code root)  |
   | Runtime             | Python 3                                                |
   | Build Command       | pip install -r requirements.txt                         |
   | Start Command       | uvicorn src.api.main:app --host 0.0.0.0 --port $PORT    |
   | Instance Type       | Free (512 MB RAM, 0.5 CPU)                              |

Step 5: Expand "Advanced" settings (Optional but recommended):
   - Health Check Path: /api/system/health
   - Environment Variables:
       PYTHON_VERSION = 3.10.12

Step 6: Click "Create Web Service".

6. RENDER FREE TIER TIPS & TROUBLESHOOTING
--------------------------------------------------------------------------------
Q: Why does the first request take 30 to 50 seconds to respond?
A: On Render's Free tier, services automatically spin down ("sleep") after 15 
   minutes of inactivity to conserve resources. When a new visitor arrives, 
   Render spins the container back up (cold start). Subsequent requests respond 
   in under 50ms.
   -> Pro Tip: You can set up a free uptime monitor (like UptimeRobot or Cron-job.org) 
      to ping `https://<your-service-name>.onrender.com/api/system/health` every 10 
      minutes to keep the service permanently awake.

Q: What if the build log shows Out of Memory (OOM)?
A: OceanEmbed's lightweight PyTorch model is strictly causal and uses under 
   250MB RAM during inference, well within Render's 512MB free limit. 
   If extra heavy packages are added later, ensure `torch` is loaded on CPU 
   mode, which is already configured in `src/api/main.py`.

Q: How do updates and new code changes work?
A: Render monitors your GitHub `main` branch. Every time you run:
       git add .
       git commit -m "update model / feature"
       git push origin main
   Render automatically triggers a zero-downtime rebuild and redeploys the site.
